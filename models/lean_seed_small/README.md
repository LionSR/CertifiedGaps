# Kernel-checked small-seed arithmetic for the longitudinal Ising chain

A partial Lean certification project: it kernel-checks (`decide +kernel`) the exact integer
arithmetic behind a two-level spectral enclosure of the 6- and 12-site longitudinal Ising
rings, and proves the exact seed conclusions of the repository's `IsingLongitudinal` model at
its first grid point **conditional on four log-partition enclosures** that are not yet proved
in Lean. It also audits, in floating point, what the same route would cost for all 43 seed
targets of the certified models ([METHOD.md](METHOD.md)).

**No certificate.** No seed becomes unconditional here; the gap at this point is already
certified outside Lean by `models/tfim_longitudinal`.

| parameter | seed (n₀, β₀) | gap ≥ (if `LogEnclosures` were proved) | lengths covered |
|---|---|---|---|
| g = 1/4, h = 1/20 | (6, 97/4) | log(13480)/(97/4) ≈ 0.3921 | none in Lean yet (even L ≥ 6 once proved) |

## Model

`H_L = −Σⱼ ZⱼZⱼ₊₁ − g Σⱼ Xⱼ − h Σⱼ Zⱼ` on a periodic ring of L sites (Pauli matrices, lengths
count sites), at `g = 1/4, h = 1/20`: exactly `CertifiedGaps.IsingLongitudinal.model (1/4)
(1/20)` in `lean/CertifiedGaps/Models/IsingLongitudinal.lean`. The checkers use the integer
matrix `A = 20H` in the computational basis (`Checker.lean`: `diagonal`, `applyH`);
`test/runtests.jl` pins its periodic-bond convention at L = 2 to that of `RPRing.hamiltonian`.

## Reflection positivity

Pauli-Z basis: `−h_bond = Z ⊗ Z`, on-site term `−gX − hZ` real. This is the repository's
`IsingLongitudinal.model` (an `RPRing` with `C = Z`), whose RP structure is checked by Lean in
`lean/`; nothing new is claimed here.

## Seeds and certified bounds

Targets (the first entry of `IsingLongitudinal.points`): `εₛ = 9064·10⁻⁹`,
`εₜ = 3141·10⁻⁸`, `r = 13480`, so the chain certificate would give `Δ_L > log(13480)/(97/4)`.

**What Lean proves (kernel arithmetic, no hypotheses).** With `S = 2⁵²` and integer vectors
`v₁, v₂` and integers `λ₁, λ₂` generated by `certify.jl`:

- `check6`, `check12` (packed lanes) and `direct6`, `direct12_chunked`/`direct12_canonical`
  (direct scalar, 64 blocks of 64 states): `|vᵢᵀvᵢ − S²|, |v₁ᵀv₂| ≤ 10⁻¹² S²`,
  `Σᵢ ‖S·A vᵢ − λᵢ vᵢ‖² ≤ 10⁻¹⁸ S⁴`, `λ₁ + S < λ₂`, `λ₂ + S < (82 − 26n) S`;
- `anchor6`, `anchor12`: exactly two classical configurations have `20·D < 82 − 21n`;
- `coverage12`, `allChunks12_eq_range`: the 64 blocks are exactly the states `0..4095`;
- `wrong_eigenvalue_rejected`, `wrong_vector_rejected`: corrupted proposals fail;
- `spatial_arithmetic`, `thermal_arithmetic`: the rational endpoint inequalities below;
- `exists_near_of_weighted_residual`: the finite weighted-sum step of the residual argument.

| ring | dimension | candidate E₀ | candidate E₁ | anchor ρ | `√Σ‖S A vᵢ − λᵢ vᵢ‖² / (20 S²)` |
|---|---:|---:|---:|---:|---:|
| 6 sites | 64 | −6.391774806847206 | −5.796599647006008 | −3.7 | 5.97×10⁻¹⁵ |
| 12 sites | 4096 | −12.78354960854822 | −11.59319932209873 | −11.5 | 1.49×10⁻¹³ |

(Decimal displays and LAPACK energies are non-certifying; the integer inequalities are the
theorems.)

**What is conditional.** `SeedBridge.lean` defines, for `Z_L(β) =
(IsingLongitudinal.model (1/4) (1/20)).partitionFunction L β = Re Tr e^{−βH_L}`,

```lean
structure LogEnclosures : Prop where
  small_upper  : log Z_6(97/4)  ≤ logSmallUpper    -- 2726798329802173/2⁴⁴ ≈ 155.0005396099
  large_lower  : logLargeLower  ≤ log Z_12(97/4)   -- 5453596500152007/2⁴⁴ ≈ 310.0010701560
  large_upper  : log Z_12(97/4) ≤ logLargeUpper    -- 2726798388197837/2⁴³ ≈ 310.0010858586
  double_lower : logDoubleLower ≤ log Z_12(97/2)   -- 2726798250076001/2⁴² ≈ 620.0021403120
```

These four rationals are, verbatim, outward-rounded endpoints in `logZ_intervals` of
`models/tfim_longitudinal/results/certificate_g1_4_h1_20.json.gz` (interval arithmetic outside
Lean); that certificate's other two endpoints (the lower end for `log Z_6(97/4)` and the upper
end for `log Z_12(97/2)`) are not needed. `spatial_arithmetic` checks
`logLargeLower − 2·logSmallUpper ≈ −9.0638×10⁻⁶ ≥ −9064·10⁻⁹` and `thermal_arithmetic`
checks `logDoubleLower − 2·logLargeUpper ≈ −3.1405×10⁻⁵ ≥ −3141·10⁻⁸`. From these,
`seed_spatial_from_enclosures` and `seed_thermal_from_enclosures` prove
`1 − 9064e−9 ≤ spatialPurity 6 (97/4)` and `1 − 3141e−8 ≤ thermalPurity 12 (97/4)` via
`1 + x ≤ eˣ`.

**Match with the repository's seed `sorry`.** On current `main`, `IsingLongitudinal.seeds`
states, for all thirty `p ∈ points`,
`1 − p.cert.sAt 0 ≤ (model p.g p.h).spatialPurity 6 p.β₀ ∧ 1 − p.cert.tAt 0 ≤
(model p.g p.h).thermalPurity 12 p.β₀`. `first_point_seed_instance (h : LogEnclosures)` proves
exactly this conjunction for `p = points[0]` (g = 1/4, h = 1/20, β₀ = 97/4), unfolding `sAt 0`
and `tAt 0` from the literal list. It does not use `seeds`. It covers one of the thirty points,
so even with `LogEnclosures` proved it would not discharge the universal `sorry`; it would give
an unconditional gap theorem for this one point.

## Reproduce

Julia 1.12, `OPENBLAS_NUM_THREADS=1`, and the pinned Lean toolchain (`v4.35.0-rc3`, via elan).
Times are on an Apple-silicon laptop.

```sh
cd models/lean_seed_small
julia --project=. -e 'using Pkg; Pkg.instantiate()'
julia --project=. certify.jl            # ~10 s: proposals -> results/certificate.json, Generated.lean
julia --project=. scripts/chunks.jl     # ~2 s: 64 direct blocks -> GeneratedChunks.lean
julia --project=. check.jl              # ~2 s: exact Julia replay of the integer claims
julia --project=. test/runtests.jl      # ~2.5 s: replay, 4 mutation rejections, convention (8 tests)
cd lean
lake exe cache get                      # Mathlib oleans (or reuse the main package's, below)
lake build                              # ~2 min with Mathlib cached
lake env lean Audit.lean                # ~15–25 s: #print axioms for 17 declarations
cd .. && julia --project=. scripts/validate.jl   # build + audit + tests + pins, ~40 s incremental
```

`lean/lakefile.toml` compiles the repository's `lean/CertifiedGaps` sources in place
(`srcDir = "../../../lean"`, same options as `lean/lakefile.toml`) into this project's own
`.lake`; nothing is copied, patched or written under the repository's `lean/`. If the Mathlib
cache host is unreachable, `cp -c -R ../../lean/.lake/packages lean/.lake/packages` (from this
directory, after building the main package) reuses its checkout of the same Mathlib commit.

Measured with this layout (sequential `lake env lean`, wall time / peak RSS): `Generated`
(packed checks, direct 6-site check, classical counts) 30 s / 4.6 GB; `GeneratedChunks`
(64 direct 12-site blocks) 48 s / 1.7 GB; `NegativeChecks` 4 s; `ChunkCoverage` 3 s;
`Arithmetic` 5 s; `SeedBridge` 53 s (mostly Mathlib import). The full `lake build`, including
the repository's `CertifiedGaps` sources, took 125 s the first time and 78 s after
regenerating the proposals.

Floating-point research tables (non-certifying, see METHOD.md):

```sh
julia --project=. scripts/feasibility.jl    # two-level trace sandwich -> results/feasibility.json
julia --project=. scripts/costs.jl --reuse  # cost model from stored benchmarks -> results/costs.json
julia --project=. scripts/costs.jl          # re-run the kernel benchmarks (LEAN_EXE, default lean)
julia --project=. scripts/report_tables.jl  # print the 43-row table
```

`scripts/inventory.jl` (→ `results/inventory.{json,tsv}`) reads other models' stored spectra
as of the PR's base commit `463c4a5`. On current `main` two of them are regenerable, gitignored
data (`heisenberg_ladder/results/verified_L8.json.gz`,
`spin1_dimerized/results/spectrum_d9_c4.json`), so rerun it at `463c4a5` or regenerate those
files first; the committed inventory is the PR's run.

## What is rigorous

- **Lean kernel, standard axioms only.** All 17 audited declarations (`lean/Audit.lean`)
  depend on at most `propext`, `Classical.choice`, `Quot.sound`; the computational checks
  use only `propext` or nothing, and none uses `Lean.ofReduceBool` (`decide +kernel`, not
  `native_decide`). Output on this build:

  ```
  check6, check12, direct6, direct12_chunked, allChunks12_eq_range,
  direct12_canonical, wrong_eigenvalue_rejected, wrong_vector_rejected   [propext]
  coverage12, anchor6, anchor12                                           (no axioms)
  spatial_arithmetic, thermal_arithmetic, exists_near_of_weighted_residual,
  seed_spatial_from_enclosures, seed_thermal_from_enclosures,
  first_point_seed_instance                    [propext, Classical.choice, Quot.sound]
  ```

  The imported `IsingLongitudinal` module contains the `seeds` `sorry`; none of these
  declarations depends on it (`sorryAx` is absent from the audit).
- **Conditional.** The seed theorems assume `LogEnclosures`. An axiom audit of a conditional
  theorem does not discharge its hypotheses.
- **Not proved in Lean.** (i) That `diagonal`/`applyH` equal `20·RPRing.hamiltonian` in the
  computational basis (the Julia test checks the convention only at L = 2); (ii) that the
  checked integer sums are the norms and Gram entries of the spectral argument; (iii) the
  correctness of the packed lane decoding in `Packed.lean` (the direct chunk route avoids
  needing it); (iv) `H ≥ D − ngI` and the min–max count turning `anchor6/12` into "at most two
  eigenvalues below ρ"; (v) rational enclosures of `exp` and the trace sandwich giving the four
  log bounds. METHOD.md estimates 900–1,950 Lean lines for these.
- **Untrusted.** `certify.jl` uses Float64 LAPACK only to propose vectors; wrong proposals
  simply fail the kernel checks. The Julia replay (`check.jl`, tests) is a diagnostic, not part
  of the trust base. Inventory, feasibility and cost numbers are Float64 planning estimates.
- **Platform.** LAPACK proposals differ across platforms (the PR's Linux run and this macOS
  regeneration gave different integer vectors); either set passes every check.

## Layout

| path | content |
|---|---|
| `certify.jl` | untrusted proposal generator; writes `results/certificate.json` and `lean/LeanSeedSmall/Generated.lean` |
| `check.jl` | exact Julia replay of the integer claims (diagnostic) |
| `test/runtests.jl` | replay, four mutation rejections, Hamiltonian boundary convention |
| `lean/` | Lake project: `lakefile.toml`, `lean-toolchain`, `lake-manifest.json`, `LeanSeedSmall.lean`, `Audit.lean` |
| `lean/LeanSeedSmall/Checker.lean`, `Packed.lean`, `Chunked.lean` | integer checkers (direct, packed, blockwise) |
| `lean/LeanSeedSmall/Generated.lean`, `GeneratedChunks.lean` | generated constants and `decide +kernel` checks |
| `lean/LeanSeedSmall/ChunkCoverage.lean`, `NegativeChecks.lean` | coverage of the block list; rejection tests |
| `lean/LeanSeedSmall/Arithmetic.lean`, `ResidualLemma.lean`, `SeedBridge.lean` | endpoint arithmetic, residual lemma, conditional seed bridge |
| `scripts/chunks.jl` | writes `GeneratedChunks.lean` |
| `scripts/feasibility.jl`, `inventory.jl`, `costs.jl`, `report_tables.jl` | non-certifying research tables |
| `scripts/validate.jl` | build, axiom audit, tests, generator hash and pins (logs in ignored `.cache/`) |
| `results/certificate.json` | integer proposals (strings), generator SHA-256, run metadata |
| `results/feasibility.json`, `inventory.json`, `inventory.tsv`, `costs.json` | non-certifying tables |

The Lake project lives in `lean/` because Lake needs its own root; `lean/.lake/` and `.cache/`
are gitignored.
